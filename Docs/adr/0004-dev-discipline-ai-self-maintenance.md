# 0004 开发纪律与 AI 自维护机制（防复发）

Status: accepted

本项目执行者是 AI（用户提供思路、AI 开发），因此长期健康的机制是把纪律**内嵌进 AGENTS.md 开发工作流**（流程路由），而非孤立的检查项。核心规则：

1. **单元提交**——任何可独立验证、可一句话解释的增量（修 bug、做优化、加工具）即一个单元，完成后立即 commit；一句话讲不清或无法独立验证 → 拆小或合并。
2. **决策闸门**——大改动前用一句话说明"是什么/为什么/风险"；硬决策（难逆转/反直觉/真权衡）必须经用户确认，并写入 `Docs/adr/`。
3. **地图同步**——结构一变就更新 AGENTS.md 与 CONTEXT.md，不允许文档脱离实际。
4. **实验留痕**——实验只进 `experiments/<name>/`（脚本 + 数据 + 结论同处一目录）。
5. **收工健康闸门**——每个流程收尾必跑（见 AGENTS.md「开发工作流」）。

背景（复盘根因）：本项目被玩坏的五个失败模式——调优无底洞（post_refactor2/3 为证）、工作不提交（7/12 后三周 untracked）、AI 功能无人背书地膨胀、文档脱离实际、实验不留结论。此五条各被一个工作流节点拦截。

Consequences: 每次动手前多花少量时间写决策/留痕，速度略降；换来可追溯、可防守——这是简历项目"能讲故事"的前提。
