# 项目报告：政策法规问答助手（RAG 领域 AI 助理）

> 版本：2026-07（基于当前代码与知识库状态整理）
> 定位：某 NLP 课程期末大作业（RAG 主线）；本报告同时给出「从 Demo 走向企业级产品」的演进路线。
> 声明：本系统回答仅供学习参考，不构成法律或行政意见。

---

## 1. 项目背景与选题

- **选题**：政策法规问答助手——面向公开政策、法规条文、政务服务办事指南的垂直领域 RAG 问答系统。
- **背景痛点**：通用大模型在政策法规领域存在知识过时、引用不清、易幻觉等问题；RAG 通过外挂权威知识库，使回答**可溯源、可验证、可拒答**。
- **合规约束**：高风险领域仅作学习参考；回答须标注「仅供学习参考，不构成法律意见」并尽量给出法条来源。

## 2. 系统现状（Current State）

### 2.1 技术栈

| 模块 | 选用 | 说明 |
|---|---|---|
| 后端框架 | FastAPI + uvicorn | SSE 流式接口，并静态托管前端，无独立前端服务器 |
| 前端 | 原生 HTML/CSS/JS（模块化） | `apiService / ragUI / messageHandler / documentManager / emojiManager / themeManager / config` |
| 向量库 | ChromaDB（本地持久化） | 持久化目录 `backend/vector_db`，当前 **3953 个片段** |
| 嵌入模型 | ChromaDB 内置 ONNX `all-MiniLM-L6-v2` | 检索路径直接使用 Chroma 默认嵌入函数，无需运行时下载 sentence-transformers |
| 大模型 | DeepSeek API（OpenAI 兼容） | 通过 `config.config` 配置，回答 `temperature=0` |
| RAG 框架 | 自研混合检索（`services/`） | 向量 + 条文号关键字 + 通用锚点，文章级切分 |

### 2.2 知识库

- **规模**：`data/raw/` 下 **21 篇**公开合规文档（含 18 部法律全文 + 3 篇办事指南），来源见 `data/SOURCES.md`。
- **构建**：`python backend/ingest.py` 加载 → 文章级切分（单条 ≤300 字，契合 MiniLM ~256 token 窗口）→ 灌入 ChromaDB。
- **可复现**：入库为确定性流程，支持运行时通过上传接口增量追加。

### 2.3 系统架构

```mermaid
flowchart LR
    U[用户] --> FE[前端聊天界面]
    FE -->|SSE JSONL| API[FastAPI /api/chat/stream]
    API --> RAG[RAGService]
    RAG --> HYB[混合召回: 向量+条文号+锚点]
    HYB --> VS[(ChromaDB 3953 片段)]
    VS -->|片段+来源+距离| HYB
    HYB --> ADAPT[自适应筛选 + 阈值判定]
    ADAPT -->|无可靠依据| REF[拒答模板]
    ADAPT -->|有依据| LLM[DeepSeek]
    LLM -->|带引用 [n] 的流式回答| FE
    FE -.->|use_rag=false| LLM2[纯大模型对比]
```

### 2.4 核心机制

1. **文章级切分**：按「第X条」切分，保证单条法条语义完整、不被相邻法条稀释。
2. **混合检索**：
   - 向量召回（候选池 12，自适应保留 ≤8 块，系数 1.8）；
   - 条文号定位：阿拉伯/中文数字归一化后子串匹配，强制顶起对应法条；
   - 通用锚点：抽取 3–4 字中文 n-gram 作为强锚点，匹配规则为「≥1 个强锚点 或 ≥2 个弱锚点」，精准召回「股东会职权」「正当防卫」类易混淆查询，同时排除「今天北京天气」等离题查询。
3. **无依据拒答**：硬阈值 `RELEVANCE_THRESHOLD=0.72` + 提示词兜底，知识库无可靠依据时明确拒答、不调用大模型、不编造。
4. **流式带引用输出**：`POST /api/chat/stream` 以 JSONL 流式返回，每块携带 `sources:[{content,source,score,chunk_id}]`，前端以 `[n]` 标注引用并折叠展示来源卡片。
5. **RAG / LLM-only 对比开关**：请求 `use_rag` 字段切换纯大模型模式，用于对照实验。

### 2.5 前端能力

聊天界面、来源引用卡片、文档管理（上传/清空/统计）、主题切换、表情、对话历史；后端同时提供 `documents/upload`、`documents/count`、`documents/clear`、`health` 等接口。

## 3. 评测结果（Evaluation）

采用 **LLM-as-judge**（裁判模型 DeepSeek）对 **53 题**评测集（25 事实型 / 16 综合型 / 12 无答案型）自动评分，维度与 Ragas 对齐；并逐题对比 RAG 与 LLM-only 回答。完整结果见 `tests/results_scored.md`，失败分析见 `tests/failure_analysis.md`。

> 说明：原计划用 Ragas 多指标编排，但其每个指标多次调用大模型，在 DeepSeek 作为裁判时单题即超时（>5 min），故改为单次调用返回多维度评分，稳定且等价。

### 3.1 评分汇总

| 维度 | 总体 | 事实型 | 综合型 | 无答案型 |
|---|---|---|---|---|
| 忠实度（无幻觉） | **4.93** | 5.0 | 4.75 | 5.0 |
| 相关性 | 4.81 | 4.96 | 4.44 | 5.0 |
| 上下文精确率 | 3.42 | 4.48 | 3.50 | 1.08* |
| 上下文召回 | 3.45 | 4.48 | 3.38 | 1.42* |
| 事实正确性 | 4.72 | 4.72 | – | – |
| 事实型来源召回率 | – | **1.0** | – | – |
| 无答案型拒答率 | – | – | – | **1.0** |

\* 无答案型精确率/召回偏低为预期（恰当拒答、无相关上下文）。

### 3.2 RAG vs LLM-only 对比

| 指标 | RAG（检索增强） | LLM-only（纯大模型） |
|---|---|---|
| 总题数 | 53 | 53 |
| 给出回答 | 32 | 53 |
| 直接拒答 | 21 | 0 |
| 事实型来源召回率 | 1.0 | — |

RAG 在「知识库无依据」问题上以拒答避免幻觉（忠实度近满分）；LLM-only 不检索，对超纲问题易凭参数记忆编造——印证了 RAG 在可信性上的核心价值。

### 3.3 主要短板（已记录于 `failure_analysis.md`）

1. **保守拒答**：约 20% 的部分覆盖问题被误拒（如「未成年人网络欺凌」「处理个人信息原则」），根因为具体条文未被顶入候选，模型依据不足而拒。
2. **检索精度/召回中等**（3.4 左右）：无重排（rerank）、单一向量召回、无查询改写。
3. **知识库规模有限**（21 篇）：部分组合/场景问题缺乏对应条文。
4. **工程化缺失**：无鉴权、多租户、审计、CI、可观测性；依赖手动评测。

## 4. 从 Demo 走向企业级产品的演进路线

当前系统是一个**功能完整的课程 Demo**。要成为可投入企业使用的产品，需在「检索质量、答案可信、知识库运营、工程化、合规」五个层面系统升级。

### 4.1 检索质量（Retrieval）

- **引入重排（Reranker）**：向量召回后用 Cross-Encoder 对 Top-K 重排，显著提升精确率/召回（当前最大短板）。
- **稠密 + 稀疏混合**：dense vector + BM25/稀疏向量融合，兼顾语义与关键词（法律术语、条文号）。
- **查询理解**：查询改写、问题分解（多跳）、实体/法名识别，把「未成年人网络欺凌」映射到「未成年人保护法·网络保护章」。
- **元数据过滤**：按效力层级、地域、时效过滤，避免引用已废止条文。
- **更大更干净的知识库**：多格式解析（docx/pdf/扫描件 OCR）、去重、版本化。

### 4.2 答案可信与安全性（Trust & Safety）

- **分级拒答**：以置信度而非硬阈值决定「直接拒答 / 弱回答+提示 / 正常回答」，减少生硬拒答。
- **引用归因（Attribution）**：逐句标注出处片段，支持点击溯源；对无法归因的陈述显式标注「模型补充，非库内依据」。
- **幻觉护栏**：输出后校验是否与检索片段一致（NLI/自洽），高风险回答强制人工复核入口。
- **模型策略**：关键场景可换更强/私有化模型，或对领域数据做微调；对回答做事实一致性约束。

### 4.3 知识库运营（KB Ops）

- ** ingestion pipeline**：可视化入库、格式解析、按文档类型选择切分策略、去重与冲突检测。
- **来源治理**：保留出处链接与发布/生效日期，支持「条文更新」自动失效旧片段。
- **人在回路（Human-in-the-loop）**：用户纠错、专家标注、错误回流至评测集与知识库。

### 4.4 工程化（Productionization）

- **鉴权与多租户**：登录、RBAC、租户隔离；敏感操作审计日志；PII 脱敏。
- **可观测性与成本**：链路追踪（LangSmith/OpenTelemetry）、延迟/令牌/拒答率监控、用量与成本看板。
- **部署与弹性**：容器化、水平扩展、向量库托管（如云向量数据库）、模型网关与降级。
- **评测进 CI**：把 53 题（及扩充集）作为回归测试，每次变更自动跑分，防止质量回退。
- **反馈闭环**：用户点赞/点踩、对话评价回灌，形成持续评估。

### 4.5 合规与信任（Compliance）

- 回答强制免责声明与来源链接；法律文本版本化；对高风险的「行政处罚/诉讼/合同」类给出「建议咨询专业律师」升级路径。
- 数据合规：知识库版权与个人信息处理符合相关法规；访问与留痕可审计。

### 4.6 建议路线图（分阶段）

| 阶段 | 目标 | 关键动作 |
|---|---|---|
| P0（加固） | 提升可信与可用性 | Reranker + 查询改写 + 分级拒答 + 补库覆盖缺口 |
| P1（产品化） | 可内部试用 | 鉴权/审计、可观测性、评测进 CI、反馈闭环 |
| P2（企业级） | 多租户对外服务 | 多租户隔离、私有化/云向量库、SLA 监控、合规审查 |
| P3（智能化） | 持续进化 | 人在回路知识运营、领域微调、主动更新与告警 |

---

## 5. 结论

当前系统已具备完整的 RAG 问答能力：混合检索、文章级切分、来源引用、无依据拒答，并在 53 题自动评测中取得忠实度 4.93、事实正确性 4.72、无答案拒答率 100% 的结果，验证了「外挂知识库提升回答可信性」的核心假设。其主要短板（保守拒答、检索精度、工程化缺失）恰是通向企业级产品的明确演进方向。按 P0→P3 路线图迭代，可逐步从课程 Demo 发展为可投入企业使用的政策法规智能助理。
