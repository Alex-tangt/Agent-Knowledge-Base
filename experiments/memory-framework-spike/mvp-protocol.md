# 个人记忆基座 MVP：开工范围与外部验收

日期：2026-10-10。状态：**验证方案，尚未执行**。依据 [owner 已确定的推进方向与 ADR 草案](../../docs/adr/0032-personal-memory-base-adopt-then-productize.md)、[交接的 S1–S3 与既定边界](../../docs/handoff-memory-base.md)。本文给开发提供验证范围；具体执行单元按仓库规则落在 issue 中。

## 问题与假设

架构方向已经足够支持第一阶段开工。需实测的假设是：一个直接采用的开源产品，能够以可接受的部署、资源、模型调用和维护成本，承接个人记忆的原文保存、只读来源接入和多 agent 共享。已有 OpenViking 隔离安装可作为第一候选起点；服务端尚无成功端到端证据，版本与运行环境应在开跑前实际确认。

## 首个开发单元

在隔离环境启动候选服务，以一条模拟移动应用提交的文本，跑通**提交 → 持久保存 → 原文读回 → 第二消费者读到同一条目**。记录实际版本、配置键名、启动方法、数据位置、引用、返回值与正文比对结果。

先解决启动阻塞并证明这条链路。两个独立客户端只能证明共享访问；完整 MVP 仍需两个实际 agent 宿主的接入证据。首个单元通过不等于整体 MVP 通过。

原文比对要看两处：**磁盘上实际存下来的字节**，以及**通过读写接口取回的正文**。检索接口返回解析后的片段不视为失败（检索本就是派生的读模型）；但**存入的原文不得被改写**。

同时回答一个形态问题：接入的项目文件是**指过去**还是**拷一份进来**。做法是接入一个测试目录 → 外部改其中一个文件 → 只应看到"同一份内容的新版本"；若出现需要双向同步的第二份正文，即为拷贝，当场登记（这条决定 M2 是否成立）。

再核两件小事：**同一请求重复提交不得产生第二条**；**接入前后来源目录的文件清单与提交号一致**。

## 设置与最小输入

- 使用候选独立环境、数据目录、端口和 namespace；不修改主 venv、真实知识库、真实索引、现有常驻 daemon 或 agent 全局注册。真实宿主验证采用隔离配置。
- 一条应用输入包含中文、Markdown、唯一测试标记与明确日期/类型路径。应用提交的总结就是这次入库的原文。
- 一个项目来源副本，含一个可被外部修改的 `.md` 文件。来源不由候选服务写入。
- 两个授权消费者：在至少一个实际范围验证只读身份与可写身份，并验证允许范围以外的访问被拒绝。
- 所有凭据通过进程环境或官方安全机制注入，证据只记录变量名与脱敏配置，不包含凭据值。
- 启动前记录服务对原文和派生内容的处理配置。写入、读取与附带处理的模型调用次数和成本分别记录；原文保存与读取不得依赖 LLM 改写。
- **环境现状（2026-10-10 复核实测）**：主 `venv/` 与候选 `venv-ov/` 的解释器均可正常执行（都报 Python 3.12.2）。上一版交接记载的 `No Python at …` **未能复现**，最可能是当时跑在受限文件沙箱下读不到基础解释器；开跑前先按现场确认当时的运行模式，**不要据此重建约 1 GB 的候选环境**。
- **版本口径不足一个版本号**：候选 Python 包为 `0.4.23`，但它的 `ov` 命令自报 `0.4.24.dev0`（`ov` 是随包发布的预编译二进制，与 Python 包不是同一条版本线）。固定版本时同时登记**安装包名与哈希**加两个版本字符串。当前隔离环境实测约 **1.06 GB / 497 个顶层目录**（旧交接的 976 MB / 171 包已过时）。
- **已定位的四个启动坑（修法可直接复用）**：① 配置文件带 UTF-8 BOM → 解析失败，必须以无 BOM 写入；② 宿主 `NO_PROXY` 含带方括号的 IPv6 → 内置客户端报 `Invalid port`，按进程注入去掉方括号；③ `openviking[local-embed]` 从源码包安装会撞 Windows 路径长度上限 → 改用 `llama-cpp-python` 的 CPU wheel；④ 文件沙箱权限不足会伪装成"解释器找不到"。
- **追溯只做最小记录**：虚拟类每次写入保留一条可追溯记录（哪个 agent、何时、哪次请求）。不建独立日志系统；实现自带的版本/快照记录能用就用。映射类不提交、不复制（见 M2）。

## 外部验收

| # | 要证明什么 | 最小观察与通过条件 |
|---|---|---|
| M0 | 能部署并启动 | 候选服务真实就绪，启动步骤和实际版本可复现；CLI 可执行或 import 成功不足以完成此项 |
| M1 | 应用输入原样保存、跨消费者共享 | 通过公开入口提交后，原文读回与输入一致；第二消费者读取同一引用得到同一正文；服务重启后仍可读取。正文比对按一致的 UTF-8 编码规则进行，不用摘要或解析结果替代原文；同一请求重复提交不产生第二条 |
| M2 | 既有资料只读接入并追平更新 | 基座可读取来源副本；通过基座写该来源被拒绝。外部修改源文件后，通过事先登记的更新机制与时限读到新正文；记录引用、版本/内容哈希变化。若实现提供导入快照，必须明确其更新步骤、延迟与成本。**接入前后来源目录的文件清单与提交号一致**；源文件改动只表现为同一内容的新版本，不出现需要双向同步的第二份正文 |
| M3 | 路径范围与授权一致 | 能按日期/类型/项目路径列举或检索，并读取返回引用。只读身份无法写，范围外的直接读取和检索均不能泄露内容；授权错误可识别 |
| M4 | 不可用与处理失败可见 | 只停隔离服务后，消费者收到明确的不可用错误；能区分无匹配、拒绝访问、服务不可用。记录附带索引/处理失败的可见状态及后续处理办法 |
| M5 | 版本、备份与恢复有效 | 用隔离测试内容证明历史版本可识别并按公开方式恢复，无需人日常审查或整理版本。再使用保存的数据、配置与公开恢复办法，在干净的隔离位置恢复；原文、引用与权限符合登记的恢复语义；**备份必须同时覆盖内容面与检索面两处存储，不能只备份一处**；检索索引可恢复或重建并查回测试内容。记录可恢复时间点和可能的数据损失范围 |
| M6 | 真实 agent 接入与成本可接受 | 至少两个实际 agent 宿主接入同一服务，完成共享内容读取与一次允许的写入；记录启用步骤、依赖/存储体积、启动/常驻资源、模型调用和维护步骤，供 owner 按个人部署条件判断。本轮先以 **DeepTutor** 作为第二接入方；随后接入**手机端 agent 的后端服务**（后端部署在本机，手机只是前端），并在这台机器上复测 |

验收先使用小数据确认行为。原有评测题集与 trace 保留；有适用适配时用于回归观察，不要求在旧题集上显著优于旧引擎才能继续 MVP。语义召回质量、抽取器、学习与画像的扩展按真实使用需求另行推进。

## 实现中可决定与需重新讨论的边界

端口、配置文件位置、现成 SDK 的调用方式、启动阻塞修复和必要的参数/错误适配，可以在隔离环境按验证目标推进。使用框架原生寻址；接入处只保留当前所需的引用、范围和明确错误，不提前建设通用后端插件体系。

若保住 S1–S3 必须改变已定部署方式、允许覆盖原文、改变来源写权限，或先重写框架的存储/权限核心才能完成首个链路，则带着实测事实重新收敛方案。无法满足当前候选的能力要求，也可以比较下一候选；这不会撤销“先采用产品验证”的推进顺序。**首个验证项（原文原样保存与读回）若不过，先带实测事实回收敛下一候选的次序，不预先锁定第二候选。**
