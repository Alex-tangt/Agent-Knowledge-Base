# rerank 延迟 vs 池大小（同场交错实测）

> 日期 2026-09-15 · 目的：**判早先"跨 run elapsed 非单调（14 比 16 慢）"是不是噪声**；给"裁池省多少延迟"一个可信数字。
> 结论：**单调 20 > 16 > 14**（3 轮 + 15/15 配对一致）；`s/pair` 近恒定 ≈0.6 → **近线性**；早先是**漂移**。

## 方法（干净测量）

- **只计时 rerank 调用**（`CrossEncoder.predict`，含其内部排序）；embedding / 向量检索 / 关键词检索 / harness 开销**不计**。
- **同场、交错 3 轮 × 5 题（q001/q003/q004/q005/q006）× pool ∈ {20,16,14}** = 每档 15 次测量；交错用于抵消机器漂移。
- 预热 1 次丢弃；`RERANK_MAX_SEQ_LENGTH=512`、`MEMORY_RERANK_MAX_CHARS=512`；索引 gen-2（134 条）。
- pairs 数**确定性**（同 pool+query 三轮一致）；另记录候选文本长度以排除长度效应。

## 数据

| pool | pairs/题 mean(min–max) | mean s | p50 | p95 | **s/pair** | sd(s/pair) |
|---|---|---|---|---|---|---|

| 14 | 15.00 (14–16) | **9.00** | 8.79 | 10.78 | 0.600 | 0.059 |

| 14 | 205 / 507.9 / 512 | 205 / 3365 / 6000 |

## 结论

1. **近线性**：`s/pair` 0.641 / 0.642 / 0.600 近恒定；最小二乘 `s = 0.728·pairs − 1.72`，**R²=0.741**，Pearson r=0.86。
2. **单调且鲁棒**：`20 (13.34s) > 16 (10.91s) > 14 (9.00s)`——**3 轮全部同向 + 15/15 配对比较一致**（16→14 平均差 +1.91s，min +0.96s）。
3. **早先"14 比 16 慢"是跨 run 漂移**：本轮逐轮极差 1.8–3.0s，**与 16−14 的差（1.91s）同量级** → 单轮非交错测量极易反号。这解释了 `pool_validation.md` 里那次异常。
4. **节省**：20→16 ≈ **−2.43 s/题（−18%）**；20→**14 ≈ −4.34 s/题（−32.5%）**。

## 环境诚实说明

运行期间 daemon（`mcp_server --transport http`，~1.19GB）+ 3 个 proxy + 其它 MCP 仍在（用户以为已全关）。但 daemon **9 分钟内 CPU 时间仅 +1.86s（≈0.35% 单核）**、工作集稳定 → **可忽略**；交错设计进一步抵消漂移。

## 局限

- 仅 5 题、n=15/档；单机 CPU；仅 rerank 调用（不含 embedding/检索/端到端）。
- 未测：embedding、向量/关键词检索延迟、端到端。
