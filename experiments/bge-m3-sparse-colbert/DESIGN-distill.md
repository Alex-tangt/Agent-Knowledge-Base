# 方案：把 rerank 排序「蒸馏」进 first-stage（数学最优参数）

> 2026-09-16 · 分支 `exp/bge-m3-fit` · 状态：**方案（待批准执行）**
> 对象 = 记忆检索 first-stage 融合参数（本地平面，gen-2 / 51 题 / 134 条）
> 目标：用 **rerank 分数**（连续、确定性、6834 个观测）作监督，求出**数学最优**的融合参数；
> qrels（45 题）**只作验证**，不进目标函数。
> 交付：`cache/rerank_scores.npz`（一次性资产）+ `fit_fusion.py` + 验证表。
> 零生产代码改动；不调 LLM。

---

## 1. 问题与关键洞察

**问题**：融合参数（用哪几条信号路、各自权重、怎么归一化）该怎么定？

**为什么不能用 qrels 调参**：qrels 只有 **45 个二值标签**。上一轮离散网格里 **88/1144 个组合都能"5/5 打赢生产"**——
这不是"很多好方案"，而是**过拟合信号**：45 个标签撑不起对 ~20k 组合的择优。

**关键洞察**（owner）：**rerank 分数是客观、稳定、连续的强相关性信号**（ADR-0022 D6 已证它与融合无关、独立打分）。
于是把问题从「拟合 45 个标签」换成：

> **求一组融合参数，使融合排序最大限度地逼近 rerank 排序。**

监督量级 **45 → 6834 个观测**；而且 **rerank 的排序正是我们目前最信任的东西**。
若逼近成功，就相当于**把重排器的排序蒸馏进 first-stage——拿到重排的收益，却不付重排的延迟**。

## 3. 融合模型：**对权重线性**

固定「归一化方式」与「信号子集」后，融合分数是权重的**线性函数**：

```
F_ij(w) = Σ_{m∈M} w_m · s_m[i,j]        w ∈ Δ_M ⊂ R^M        (M ≤ 5)
```

这一条是整个数学方法成立的基础：**目标关于 w 是线性的**（非线性只来自"排序"这个操作）。

**归一化**（逐 query、逐信号；离散选择，见 §6）：`none` / `minmax` / `zscore` / `rrf(k=60)`。
> `none` 在含 sparse 时已经实测崩掉（sparse 原始分 max 15.4 vs 其它 0.8，量纲差 7–20 倍）→ 归一化是必需项，不是可选项。

---

## 4. 目标：两个排序有多"接近"

四种标准度量（都在每题内算，再对 51 题取平均）：

| 度量 | 定义 | 特点 |
|---|---|---|
| **Spearman ρ** | `1 − 6Σd²/(D(D²−1))`，d = 名次差 | 全序一致；无量纲 |
| **nDCG@k（蒸馏）** | 把 `R[i,·]` 归一化成 gain，看融合前 k 的 gain 覆盖 | **贴消费者**（agent 读前几条） |
| **Kendall τ** | (同序对 − 逆序对) / 总对数 | 等价于"成对偏好一致率" |
| top-1 / top-3 重合 | 集合交集 | 最直观 |

---

## 5. 为什么不能"直接对 Spearman 求最优"（数学上的坎）

排序是**阶梯函数**：名次只在跨越超平面 `w·(s_a − s_b) = 0` 时改变。
因此在单纯形 `Δ_M` 上：

- Spearman / Kendall / nDCG **在每个"胞腔"（cell）内是常数**，梯度**几乎处处为 0**；
- 目标**非凸、非光滑**（是单纯形被 ~`M·C(D,2)` 个超平面切出的一个**排列划分**）；
- 直接梯度上升无从下手；穷举胞腔 = 变相的网格搜索。

**结论**：不存在"直接最大化 Spearman 的解析解"。正确做法是——**换一个凸的等价/代理目标，求其全局最优，再用真实指标验证**。
这就是"数学最优"在本问题上的**确切含义**（这一点必须对读者讲清楚，否则是过度宣称）。

## 6. 两条凸代理（都有**全局最优**）

### 代理 A：成对偏好（RankSVM / Logistic）— 与"排序接近"最贴合

把 rerank 排序拆成**成对约束**：

> 对每题 i 的每对 `(a,b)`，若 `R[i,a] > R[i,b]`，则希望 `F_ia(w) > F_ib(w)`。

令特征差 `x_p = s[i,a] − s[i,b] ∈ R^M`（**对 w 线性**），样本权重 `c_p = R[i,a] − R[i,b]`（分差越大越可信）。

**加权 logistic 损失**（平滑、可导）：

```
L(w) = Σ_p  c_p · log( 1 + exp( − w·x_p ) ) + λ‖w‖²
```

`w ↦ w·x_p` 是线性的，`log(1+exp(−·))` 是凸的 → **L 是凸函数**；约束 `Δ_M` 是凸集。
→ **凸优化，全局最优**。（也可用 hinge 版 `Σ c_p·max(0, 1 − w·x_p)`，非光滑但同样凸。）

**理论理想（先判可行性）**：若存在 `w` 使 **所有** 成对约束同时成立（`w·x_p ≥ 0 ∀p`），
则能**完全复现** rerank 排序——这是一个**线性规划（LP）**可否行的问题。
现实中大量成对偏好互相冲突（rerank 分数是交叉编码器，不保证能被线性融合完全再现）→ 一般不可行，
故退回到上面的 hinge/logistic（LP 不可行 ⇒ 用凸松弛）。**先跑一次 LP 判可行性**，是很干净的论证起点。

### 代理 B：分数回归（带单纯形约束的最小二乘）

把 `R[i,·]` 逐题归一化成 `r̂[i,·]`（min-max → [0,1]，或名次增益 `(D−rank)/D`），直接拟合：

```
min_w   Σ_i Σ_j ( F_ij(w) − r̂_ij )²      s.t.  w ∈ Δ_M
```

展开即 `min ‖A w − r̂‖²`（`A ∈ R^{6834×M}`）→ **带线性约束的二次规划（QP）**，凸 → 全局最优。

**而且 M ≤ 5 时能精确求解**（活跃集枚举）：最优解必在单纯形某个面内（把一部分权重压到 0）。
枚举全部 `2^M ≤ 32` 个活跃集 `T`，在每个面上解**等式约束最小二乘**：

```
w_T = (A_Tᵀ A_T)^{-1} ( A_Tᵀ r̂ + μ·1 )
μ   = ( 1 − 1ᵀ (A_Tᵀ A_T)^{-1} A_Tᵀ r̂ ) / ( 1ᵀ (A_Tᵀ A_T)^{-1} 1 )     ← 使 Σw_T = 1
```

保留 `w_T ≥ 0` 的候选，取代价最小者 → **精确全局最优**（32 次 ≤5×5 线性方程组，微秒级）。
> 这是个漂亮的点：**问题小到可以精确求解，不需要迭代优化器**。

### 求解器

- 代理 A：**投影梯度下降（PGD）**，投影到单纯形用 water-filling
  （排序 `v` 降序，取 `ρ = max{k : v_(k) − (Σ_{i≤k} v_(i) − 1)/k > 0}`，`w_i = max(v_i − θ, 0)`，`θ = (Σ_{i≤ρ} v_(i) − 1)/ρ`）——O(M log M)，零新依赖。
  用 `scipy.optimize.minimize(SLSQP)` 交叉验证收敛点（已装 scipy 1.18.0）。
- 代理 B：**活跃集枚举（精确）**；`scipy.optimize.lsq_linear` 作独立复核。

## 7. 外层离散选择 + 交叉验证

归一化（4 种）与信号子集（colbert 只取一档 → 23 个非空子集）是**离散**的，塞不进同一个凸问题：

- 外层：`4 × 23 = 92` 个凸问题，每个微秒级 → 总耗时 < 1 秒。
- **交叉验证**：另跑**离散网格 E2E**（权重步长 0.05，~20k 组合）→
  凸解与网格最优**must 落在同一片区域**；差很远 ⇒ 代理目标没对齐，需查（这是对"数学最优"的独立检验）。
- **取平台不取峰**：对最优解做 **paired bootstrap**（对 51 题有放回重采样 B=2000）→
  报告指标的 95% CI；平台 = CI 内不可区分的解集合，取其中点（沿用当年定 β∈[0.05,0.08] 的纪律）。
  45 题下的单点最优**不可信**，这一条是防自欺的关键。

## 10. 边界与风险（必须随结论一起报）

1. **rerank 是代理，不是真相**：我们优化的是"像重排器"，它的偏差会被继承。
   → 用 L3 qrels 验证 + （可选）第二个重排器交叉复核。
2. **继承 512 字截断的偏好**（与生产一致）。
3. **线性可达性**：融合是线性的，重排是非线性的（交叉编码器）。若二者排序差异本质不可被线性组合逼近，凸解会给出"最优但不够好"——这本身就是有价值的结论（说明需要更复杂的融合，如分段/树模型）。
4. **仅此语料+题集**：换语料/题集要**重录矩阵**（`rerank_scores.npz` 是可复用资产）。
5. **离线能"排除"不能"证明"**：真进默认链路仍要跑一次真实 store 链路（本仓纪律）。
6. **qrels 无泄漏**：qrels 不进目标函数，只作 L3 验证——这是本方案比"直接网格调参"更可信的根本原因。
