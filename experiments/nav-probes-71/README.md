# nav-probes-71 — 导航探针 vs 一次性检索（#71 线② 评测基座）

> 探针数据与口径在 `memory_agent/eval/standard_sets/nav_probes_71.{json,spec.md}`；
> 执行器 `memory_agent/eval/eval_71_nav.py`；总证据 `memory_agent/eval/eval_71_results.md`。

## 问题

`#63` 要给检索 agent 加 **grep / read（行范围）/ outline / history** 四种导航动作。在写工具之前必须能回答：
**这四种动作覆盖的面，现有一次性向量检索（`MemoryIndex.search`）到底做不到什么？** 没有任何公开
RAG 标准集覆盖这个面（MultiHop-RAG / BEIR 只测语义相似检索），所以要自造一组**机制探针**。

## 假设

- **H1**：对"定位到具体 token / 行窗 / 标题 / 提交"的任务，一次性检索（条目级 top-k）**覆盖率有限**
  ——大条目的局部细节被稀释、词典外 token 无区分度。若 `recall@14 ≪ 1`，导航面有头寸。
- **H2**：`history`（提交轴）与**代码文件**对一次性检索是**结构性不可达**（索引只装 `.md` 的终态快照）。
- **H3**：H1/H2 的缺口就是 `#63` 的测量面；probe 需可**失活**（文档一改就报 stale），否则会变成"永真集"。

## 设置

- 对象 = 本仓**真实基表**：可写 KB（`AGENT_KB_DIR`，≈30 条有 frontmatter id）+ 只读语料
  （仓库内 `.md`，label `agent-knowledge-base`）+ 其 **git 历史**。
- 28 条探针，四条面：`grep` 10 / `read` 7 / `outline` 5 / `history` 6；其中 `scope=repo` 的代码边界 3 条、
  `scope=kb` 3 条。每条带**参考动作**（该做的那一次导航调用）+ 期望位置（文件/行窗/标题/提交）。
- 17 条 `corpus` + 2 条 `kb` = **19 条可寻址**（有 `baseline_entry_id`）；9 条**结构性不可达**
  （6 条 history 无提交维度 + 3 条代码文件不在索引里）。
- 对照链路 = **生产记忆检索链**：`MemoryIndex.search`（BGE-M3 dense + BM25 sparse + store 原生 **DBSF**，
  rerank 关，`MEMORY_RETRIEVAL_POOL=14`）；条目级命中（与 #24/#47 同粒度）。
- **隔离**：索引在 `%TEMP%/eval71-nav/index`（生产 `gen-4` 的副本 + 惰性增量追平）；`--verify` 与
  `--baseline` 都排除本票自己的产物（探针/规格/结果）——否则会拿"我自己的题面"当语料自我验证。

## 结论

> **导航臂的 1.0 是「Python 复刻的参考动作」的结果，不是 LLM agent 的成功率**；Δ 度量的是
> 「**面**（能问到什么）」的差，**不是 #63 工具的体验增益**。#63 必须自己跑真 agent 才能声称
> "agentic search 显著优于一次性检索"。

**H1 成立（有头寸）**：条目级一次性检索在这组导航任务上 `recall@14 = 0.737`，paired
Δ(导航参考动作 − 一次性 top-14) = **+0.263，95% CI [+0.105, +0.474]**（显著）。
**H2 成立（结构性不可达）**：9/28 的任务一次性检索按定义无解。
**H3 落地**：探针带锚短语 / 位置 / 提交 sha 断言 —— **位移**用 `--refresh` 修（不改语义），
**锚短语消失**则报**真失效**；两种都不会假通过（2026-10-07 实测：一例位移、一例真失效）。

**边界（不得越读）**：
- 导航臂的 1.0 是**参考动作**（Python 复刻）的结果，**不是 LLM agent 的成功率**；Δ 是"面"的差，不是"工具体验"的差。
- n=19 → CI 宽（±0.21）；本集是机制探针，不做分布推断。
- 外部语料只作机制证据、不声称本库增益（ADR-0026 D5/D6）；本集是**自造机制探针**，也不是 in-domain 集（#65）。
