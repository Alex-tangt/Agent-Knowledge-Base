# 去重阈值校准（DEDUP_THRESHOLD，#16）

## 问题

`memory_add` 写前用派生索引检索，命中相似度 `>= DEDUP_THRESHOLD` 即判为近似重复、
只报告不写。该阈值初值 `0.92` 是**暂定 knob**（ADR-0009 D3：偏保守，宁漏报不误报），
校准被记在 #16 名下。现在回答：**0.92 是否合适？应该调高、调低还是保持？**

## 假设

真实 KB 的条目彼此主题相近（都是 agent/记忆/训练相关），天然相似度不低；若
「最近邻」分布已经接近 0.9，则 0.92 的风险是**误报**（把一条不同的事实判成重复），
而不是漏报。反之若最近邻明显更低，说明阈值可以下调以多捕获同义重加。

## 设置

- 数据：真实 KB（`C:\Users\Tan\.config\opencode\knowledge`）已**提交态**，`git clone`
  到临时目录——读写隔离，可复现（不受并发会话的在制品影响）。
- 索引：只含可写条目（`MEMORY_READONLY_ROOTS=""`），临时 `MEMORY_INDEX_DIR`，
  经文档化的 `memory_agent/build_index.py` 构建（与 sandbox 同一口径）。
- 度量（读路径，不写 KB）：对每个条目构造三种查询，走真实
  `MemoryIndex.search(writable_only=True)`，`k = 条目数`：
  - `full` = `f"{title}\n\n{body}"`：与写入网关写前查询**逐字一致**（精确重加）。
  - `body` = 去标题前缀的正文（同义重加的近似代理）。
  - `title` = 仅标题（极限压缩代理）。
  - **正例分** = 查询命中自己的分数（低于阈值即漏报）。
  - **负例分** = `full` 命中别的条目的最高分（不低于阈值即误报风险）。
- 运行：`venv\Scripts\python.exe experiments/dedup-threshold-calibration/calibrate.py`
  （加载一次 BGE-M3；CPU）。

## 结论

<!-- CONCLUSION:START -->
**建议 `DEDUP_THRESHOLD` 0.92 → 0.88。**

- 精确重加（`full`）最低 0.949，只比 0.92 高 **0.029**——留白太窄：重加时措辞略有变动
  就会掉到 0.92 以下而被漏报。
- 最近邻（不同条目）最高 0.792，0.88 仍有 **0.088** 的误报余量。
- 0.88 落在实测间隔 [0.792, 0.949] 的中间，扩大「同义重加」捕获带（0.88–0.95），
  且不降到实测负例之上。
- 已回写：`memory_agent/settings.py` 默认值 + `docs/adr/0009`（校准小节）。

**残留不确定性**：本实验没有 LLM 同义改写样本（改写需模型、非确定性），正例用「去标题
前缀」代理；真实同义重加分值可能低于 0.949，故 0.88 仍偏保守。若后续引入改写样本，应复校。
