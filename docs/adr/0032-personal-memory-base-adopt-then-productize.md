# 0032 个人记忆基座：先采用开源产品，再按使用证据裁剪并独立产品化

Status: **proposed**（2026-10-10）。owner 已在对话中明确推进方向；本文是按仓库规则起草的决策记录。阶段完成条件为架构建议，具体产品、版本和提取模块仍待实践确定。

Relates: [需求与既定边界](../handoff-memory-base.md)、[架构咨询](../architecture-personal-memory-base.md)、[ADR-0031](0031-monorepo-dual-product-kb-and-retrieval-agent.md)。本文记录个人记忆基座的新阶段路线，不报告实现完成，也不更改检索 agent 的独立部署与接入边界。

## 背景与权衡

直接采用已有产品可以较快取得真实使用证据；提前裁剪两个框架会同时承担选型、集成和维护责任。AI 已降低理解和改造源码的成本，待需求与模块边界明确后，复用上游代码组成自主产品具有可行性。因此先验证低成本可用性，再依据实际缺陷确定要保留、扩充和剥离的实现。

## 决策

- **D1 推进顺序**：直接采用低成本开源产品跑通 MVP → 在实际使用中筛选、扩充能力并完善架构 → 给出私有化产品计划 → 依据计划剥离冗余，交付完整、可独立部署的产品。
  - 第一候选沿用已隔离安装的 OpenViking。owner 的选型理由是：**它「目录 + 权限 + 版本」的形态是本人能读懂、也最贴合需求的一种存储方式**（一个人加 AI 维护的系统，"我能不能读懂"是正当的选型依据，不必用评测分数替代）。这是**排序理由、不是结论**：本轮不判定它最优；首个验证项（原文原样保存与读回）若不过，带实测事实回收敛下一候选，不预先断言唯一路径。
- **D2 MVP 范围**：先完成个人记忆的存储与检索。多个 agent 共享同一份人的记忆；既有项目资料只读接入，应用提交内容原样保存；派生内容另存；范围权限、版本与备份可恢复、不可用时显式报错。先在家用 PC 部署，不将学习、画像或简报作为首期前置。
- **D3 演进方式**：功能增补与架构调整对应实际使用中的问题，保留可复现记录和验证依据。配置、公开接口、模块提取和受控 fork 均可采用；每项能力选用方式由效果、运行成本和维护范围决定。最终剥离范围在产品计划中明确。
- **D4 独立产品化**：产品掌握自身接口、数据契约、安装与运行流程、升级迁移、备份恢复和维护责任。允许保留成熟开源依赖及许可允许复用的上游代码；依赖和运行方式须明确、可复现。私有化部署从 MVP 即开始，最终产品化阶段完成可交付的独立产品形态。
- **D5 既有资产**：旧自研引擎按交接既定方向冻结、保留证据；agent 接入面与评测资产继续保留并演进，不因换后端而丢失。
- **D6 接入方**：本轮先用 DeepTutor 作为第二接入方做共享验证；随后接入手机端 agent 的后端服务（后端就部署在这台电脑上，手机只是前端），并在这台机器上复测。换后端不取消真实宿主的接入验收。
- **D7 版本与追溯**：版本由选定实现自行维护，不要求人日常审查或整理历史。**映射类（项目文件）不复制、不提交**——它的版本留在各自项目仓库，基座只记录"读到的是哪个版本"；只有虚拟类（app 提交的内容）的版本落在基座侧。虚拟类每次写入保留一条可追溯记录（哪个 agent、何时、哪次请求）：**不建独立日志系统**，实现自带的版本/快照记录能用就用，缺身份时在接入层留一行。
- **D8 许可**：已核实已安装的 OpenViking 0.4.23 为 **AGPL-3.0**（dist-info `License-Expression`，源码头 `SPDX-License-Identifier`）。个人自用、不对外分发不触发义务；但若按 D4 裁剪上游代码组成自己的产品，该产品须按 AGPL 发布。**owner 已接受这一代价。**

## 分阶段完成条件（建议）

| 阶段 | 主要产物 | 完成条件 |
|---|---|---|
| 1 采用产品跑通 MVP | 固定版本与配置、隔离部署、真实读写链路证据 | 应用提交后原文可读回，第二个 agent 能读取同一内容；只读来源与更新、范围权限、不可用错误和恢复可验证；记录实际运行成本 |
| 2 使用中筛选与扩充 | 真实问题记录、必要改进、逐步明确的模块边界与架构 | 主要问题有复现与验证；每项能力的输入、输出、可写范围、失败状态和维护归属明确 |
| 3 给出产品计划 | 产品范围、保留/剥离清单、模块来源与许可、目标部署架构、迁移与维护计划 | 实施范围和顺序可执行；安装、升级、数据迁移、恢复与验收方式明确 |
| 4 裁剪并独立产品化 | 精简实现、可交付安装包或部署产物、用户与维护文档 | 干净环境可独立安装、运行、升级和恢复；保留的接入与评测通过；冗余剥离后的运行与维护成本有证据 |

阶段 1 的低成本同时考虑部署、资源、模型调用和维护成本。阶段 1 不预设最终源码组织；阶段 2 不以发现缺陷为由重开旧引擎演进。具体版本、模块提取与数据格式变更在相应阶段另行收敛。

## 实测补充（2026-10-10，阶段 1 执行完毕）

验收口径与逐项判定见 [mvp-protocol.md](../../experiments/memory-framework-spike/mvp-protocol.md) § 结论；证据见 [mvp/](../../experiments/memory-framework-spike/mvp/README.md)、[memory-host-connect/](../../experiments/memory-host-connect/M6-report.md)、[memory-spike-verify/](../../experiments/memory-spike-verify/verify_conclusion.md)。**M0–M6 均有真实实测证据**（M5 为条件化通过：嵌入提供方必须进程外）。

与本文前述设想**不一致**的实测事实，登记在此，供阶段 2 收敛：

1. **"映射类"在本候选上不是"指过去"，而是"导入快照 + 显式重推"**（本地路径 watch 被框架显式拒绝；重复导入会生成第二份正文）。因此"来源更新"没有自动追平，**读到旧快照也没有任何信号**（`stat`/`attrs` 不带来源哈希或 mtime）。这与架构咨询 §3 对映射类的设想有偏差：要么在本仓补一个"来源指纹 + 漂移检查"的薄层，要么在阶段 2 重新评估候选。**这是阶段 2 的第一顺位议题。**
2. **账户级 ACL 默认关闭**（开关 `acl.enabled`）：不显式打开时 `restricted`/`grant` 完全不生效、**只读身份也能写**。单用户部署也不能默认依赖权限生效。
3. **备份包不含身份/API key 注册表与 ACL 记录**，干净位置恢复后须重建；恢复是**离散点**（快照 / 备份包时刻），回不到任意时刻。
4. **候选自带的 in-process 本地 GGUF 嵌入器并发不安全**（整进程 abort）；嵌入放进程外并串行可规避。部署形态选择须据此确定（D6 的权威点机器上要跑一个进程外嵌入服务）。
5. **服务器实际注册 20 个 MCP 工具**（代码注释里的 16 是旧值）：宿主 `enabled_tools` 白名单必须按实测工具名写，否则新工具静默不可用 —— 直接影响 D6 的接入验收做法。
6. 附带处理的**状态字段不可信**：`semantic_status=complete` 时目录摘要仍可能是占位符；派生内容的状态需要独立可见信号。

## 部署与真实使用增量（owner 已授权，2026-10-11）

owner 将下一步优先级收敛为**可部署、可接入、真实使用验收**，并明确要求把 Agent-bubble 的实际 pi 后端接到知识库，使文章与视频总结可以写入和读取。来源新鲜度仍是已登记缺陷，不再作为此增量的前置。

- **D9 正式运行边界**：新增独立 `memory_base/` 薄运行包，复用固定版本 OpenViking 0.4.23；旧 `memory_agent` 引擎保持冻结。统一安装与生命周期命令管理 OpenViking、进程外串行嵌入服务和接入服务。实验实例与正式实例分开，不依赖实验脚本中的绝对路径。
- **D10 共同接入语义**：HTTP 与 MCP 共享 `memory_add` / `memory_search` / `memory_get` 实现。宿主身份由凭据绑定；只读身份拒绝写入。普通宿主只追加 capture，不暴露覆盖、删除、账户管理工具；确定性请求地址及请求哈希保证重试不重复、内容变化不覆盖。正文与追溯元数据分开保存，正文不添加前言或被模型重写。
- **D11 Bubble 完成语义**：pi 注册上述工具；首个成功总结由程序原样保存，普通追问不自动产生新总结。总结生成与知识库保存分别报告状态，保存失败保留本地结果并可重试。知识库不可用必须明确报错，不能作为“未找到内容”。
- **D12 凭据与权限**：OpenViking 使用 key 模式并显式开启账户 ACL。Windows 正式部署使用系统凭据管理器提供凭据，再注入进程环境；其它平台支持进程环境。配置、日志、验收记录不写明文凭据。
