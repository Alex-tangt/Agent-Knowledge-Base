# 0025 个人模式：以「文件 + git」为基表的知识数据库模型

Status: **accepted**（2026-09-16 用户拍板）。

Amends: **ADR-0015**（其"两平面"主轴被本条的"所有权轴 + 部署轴"取代）；收窄 **ADR-0006** 适用范围到单写者；
把 **ADR-0014** 的只读语料推广为「收录 / 域」的一般机制；给 **ADR-0011** 的刷新加一条"查询时惰性触发"。

## 背景

Post-MVP 的"私有本地 / 企业云"把**所有权、并发、部署**三件事压成了一根轴，于是"云 vs 本地"看起来像产品形态，而云平面长期没有可见功能（`PLANE_CLOUD` 无实现、无联邦）。同时出现两个真实驱动：**多消费者共享同一知识**（opencode / DeepTutor 等，避免每个软件把知识切成小块）与**成本可接受的新鲜度**。本条把这套形状重新定为**一个数据库模型**，而非"两个平面"。

## 决策

- **D1 本质 = 知识数据库**：**基表 = 版本化纯文本（文件 + git）**；**索引 = 派生 ANN**（可重建、可丢弃）。既不是"目录遍历"也不是"向量库单源"。
- **D2 一张基表**：条目（entry）= 行；**收录**决定基表的 extent（DDL）。
- **D3 域 = 基表按 `owner` 切出的行子集 + 该子集的写授权**；不是容器 / 命名空间。
- **D4 视图 = 基表上的具名读谓词（只读）**；**读走视图、写走域**；最终可见 = **视图 ∩ 身份授权**（网关强制收窄，ADR-0018 D2 / #32）。
- **D5 集合 = 物理 ANN**，按**同构**切分（同嵌入模型 / 同粒度）；**一份集合服务任意多个视图**，视图是查询期过滤、**不物化**（否则 N 域 → 2^N 个视图组合爆炸）。
- **D6 主体 = agent（按软件）**：一软件一令牌；**权威 = 部署者**（审计记 agent，授权由部署者发）。
- **D7 联邦 = 中央索引（A）**：本机一个 daemon **就地索引**所有**文件可达**的域；跨机器 / 异构嵌入才需联邦服务（B），后延。
- **D8 收录 = 注册表默认 ∪ 显式 overlay（独立清单）**；粒度 = **路径模式**（精确文件 / 窄 glob；收整棵子树须配 exclude）；`owner` 默认按来源、**特殊收录可显式指定**。
- **D9 新鲜度 = 查询时惰性刷新**：`memory_search` 前做廉价指纹检查（stat `mtime`+`size`），只对变更条目重嵌；**不使用文件监视器**（零依赖、零常驻线程、无 Windows 事件坑）。
- **D10 外部软件直接写自己的文件**（我们是其**只读索引器 + 权限层**）；写入网关（add/supersede/archive）只覆盖**我们自己的行**。
- **D11 多写者 = 仅"同一域被多方共写"时才需真 DB**；每行单写者下，**文件 + git 就是正确的数据库**。
- **D12 语料 = 精选的静态、重要文档**（ADR / AGENTS.md / CONTEXT.md 等），**不遍历工作空间**。

## 理由

- **对齐数据库心智**：表 / 视图 / 索引 / 所有权各有其位，模糊的"库"消失（`CONTEXT.md` 词汇已改）。
- **反碎片化**：共享的是**基表（可读纯文本）**，索引只是派生副本——不同软件可各建索引而不割裂知识。
- **成本**：惰性刷新 + 精选静态文档 ⇒ 无 watcher、无轮询、变更稀少，绝大多数查询零额外成本。
- **可演进**：`VectorStore` 端口 / "视图=谓词" / agent 身份三个**不变量**，使"共写域 → 换真 DB"不推翻现有设计。

Considered options：
- **A 文件+git 基表 + 派生 ANN（采用）**——人可读、可迁移、零锁定；代价是并发/新鲜度要自己管。
- **B 向量库单源（弃）**——丢版本 / 人读 / 可迁移（同 ADR-0006）。
- **C 一视图一物化索引（弃）**——组合爆炸。
- **D 现在就上多写者 DB（弃）**——个人模式无共写需求，成本前置。

## Consequences

- **ADR-0015 D1 的"两平面主轴"被取代**：所有权（个人 / 共享）与部署（本地 / 托管）分离；"企业云"= 共享模式的托管形态，**只有在出现第二写者 / 共写域时才有意义**。
- **ADR-0006 适用范围收窄到单写者**；多写者（共写域）时 **DB 即真相源**。
- **ADR-0014 的"只读语料"推广为收录 / 域的一般机制**（只读域 = 无写者）。
- **ADR-0011 的刷新新增触发**：查询时惰性检查（写后钩子是否保留见"未决"）。
- **实现缺口（下一步，非本 ADR）**：语料/注册表目前 **import 时定死**（`READONLY_ROOTS`）→ 支持 overlay 收录需**运行时重读 selection**，并安全处理条目消失（ADR-0014 的孤儿风险）。
- **命名迁移**：代码里 `KBRegistry` / `kb_name`（含**公开 API 参数**）待独立迁移票；本 ADR 只定概念。

## 追加决策（2026-09-16）：三条未决已定

- **D13 刷新触发 = 仅查询时惰性刷（弃写后同步刷）**：`memory_add` / `supersede` / `archive`
  **不再在写入路径触发刷新**；索引更新一律由下一次 `memory_search` 的指纹检查驱动（D9）。省一次嵌入、
  简化写路径。**修订 ADR-0011 D3**——"写后钩子"降级为**移除/可选**（写入只落真相源，索引追上由查询驱动）。
- **D14 v1 视图 = 单一默认视图，预留具名视图缺口**：v1 不给视图起名，检索范围 = 当前 agent **可见的
  全部域**（授权收窄之后）；但**保留"视图 = 谓词"的接缝**（查询参数里的过滤层，今天的 `writable_only`
  即一个未命名视图）——加具名视图时**不改接口形状**。
- **D15 授权表 = agent →（可见视图, 可写域）**：扩展 `#32` 已有的 token→身份 映射
  （`MEMORY_AUTH_TOKENS`），为每个软件增加**可见视图集**（读）与**可写域的所有者集**（写，通常只有自己）。
  这是**配置/DDL**，不是数据。**凭证（token 值）绝不提交**——表结构可入库，token 材料走进程环境 / gitignored。
- **D16 共享模式 = DB 即真相源，写路径按域 `plane` 分叉**：共享域写入走 **DB 事务**（并发交给 DB，不做自定义冲突处理）；**本地专用机制（git commit / 代目录 / 指针切换 / 惰性重建）仅用于本地域**，不外溢到共享域。其余照标准多租户 DB 设计：软删除（`status`）/ 审计 / 网关强制隔离（云托管无行级 RBAC，ADR-0018 D2 不变）；知识语义（supersede/archive/去重/条目粒度）与嵌入（BYOE）仍属 app 层。

## 追加决策（2026-09-16 续）：第二消费者 = 共享服务（#41）

> owner 拍板 2026-09-16：「深·共享服务」+ **维持只读边界**；据此派发 #41。

- **D17 多消费者共享 = 共享服务，不是各建索引**：同一台机器上的第二个 agent 软件（如 DeepTutor）
  **不新建服务端、不复制引擎 / 索引**；它作为 **MCP `streamableHttp` 客户端**连**同一个常驻 daemon**
  （`/mcp`）。共享**服务**即天然共享**基表 + 派生索引**（D1 / D7）；这也正是"反碎片化"（D1 理由）的落法。
  - **登记位置 = 部署级 MCP 配置**（本机部署者可写），**不是**第三方软件的 per-user 自服务配置——
    后者对本机回环走严格 SSRF 屏障、且对 `stdio` 关闭（第三方软件的加固默认），本机共享不适用。
  - **默认只读边界**：第二消费者 v1 只用**读**工具（`search` / `get` / `index_status` / `ingest_list`）。
    写仍只走本产品的写入网关；外部软件要写就**直接写自己的文件**，由我们**只读索引**（D10）。放开写 = 另票。
  - **不碰第三方软件自带的 KB 功能**：不做其 KB 文件格式的解析 / 互链（避免耦合到外部产品的内部形状）；
    共享只发生在**基表 + 服务**这一层。
  - 与 D15 的关系：每个消费者 = 一个 agent 身份（token → 可见视图 / 可写域）；本机单部署者下
    **不强制 token**（ADR-0018 D2 的 `require_token` 默认按"是否配了 token"决定），零配置即可直连。
