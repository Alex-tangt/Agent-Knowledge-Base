# 0021 记忆检索优化的验收指标：以 recall@1/MRR 为主，nDCG@10 为辅助头条

Status: proposed

## 背景

`#24` 建了确定性评测基座（条目级二值；`recall@k` / `nDCG@10` / `MRR`；不调 LLM）。`#28` 把守门定为「**nDCG@10 ≥ 基线 0.9658**」。池裁剪实验中（`experiments/rerank-latency-survey/pool_{results,validation}.md`）暴露问题：

- 在记忆语料上 **recall@10 基线已达 0.985**（gold 基本都捞得到）→ nDCG@10 实际主要在量**排序**，不再量检索。
- 差异**高度集中在少数多 gold 题**（q010 有 4 个 gold；q042 单题可动均值 0.02），样本仅 45 题 → 「nDCG@10 ±0.005 过没过线」本身很脆。
- 实测 pool 12/14/16 **非单调**（12 挂、14 超基线、16 逐位打平）→ 单看一个头条数字容易做出脆弱结论。

同时**未从"谁消费检索结果"反推指标**：记忆检索的消费者是 agent（`memory_search` 返回 top-k 条），而 nDCG@10 的"前 10 条整体覆盖"更像 RAG 喂 LLM 的场景。

## 决策

- **D1 主指标 = `recall@1` + `MRR`。** 理由：对应 `memory_search` 的真实消费（agent 取最相关条目），"最优条目是否在最前"最贴用户体验。
- **D2 辅助指标 = `recall@k`（k = 实际返回条数）+ `nDCG@10`。** 前者管"返回的那几条里有没有 gold"，后者**保留为标准可比头条**（对外/跨系统）。
- **D3 守门口径 = 主指标不退化（在样本噪声带内），辅助指标**一并报告；**不再单以 nDCG@10 划线**。
- **D4 报告纪律**：任何检索改动必须同时给出 `recall@{1,k}` / `nDCG@10` / `MRR` / `misses` + 候选规模（pairs），并注明样本量与该指标的噪声带。

## 理由

- **指标要对应消费者**：agent 记忆检索要"第一条对"（D1），而不是"前十条覆盖全"。
- **二值 + 小样本 + 多 gold** 使 nDCG@10 的微小差异噪声化（D3）。
- **对外可比性**仍要保住 → nDCG@10 不作主指标但保留为头条（D2）。

Considered options:

- **A 主 recall@1/MRR（采用）**——贴 agent 消费；代价：对外不比 BEIR 式 nDCG。
- **B 维持 nDCG@10 为主（弃）**——标准，但在本语料/样本上已退化为排序噪声，易得脆弱结论。
- **C 改用分级相关（graded nDCG）（弃）**——更细，但标注成本高，且 #24 的评测集是二值。
- **D 改用下游任务指标（LLM-as-judge）（弃）**——非确定性，违背 #24「不调 LLM、可复现」的设计。

## Consequences

- 池/top-k 等排序类决策改用主指标判；已做的池实验结论按新口径**复核**（pool=14 的 recall@1/MRR 优于基线 → 在新口径下更稳）。
- `#28` 式"nDCG@10 单线守门"作废（`docs/adr/0020` 的 D 若涉及，以本 ADR 为准）。
- 对外仍报 nDCG@10，保持与 BEIR 类口径的可对话性。
- **未决**：主指标的"噪声带"具体多大（需用样本量/自助法界定，另立小任务）。
