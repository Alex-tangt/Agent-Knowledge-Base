# 0006 记忆架构：Markdown 真相源 + 派生索引 + 写入网关生命周期

Status: accepted

记忆的真相源是 **Markdown 条目**（内容 + frontmatter 元数据，git 版本化）；检索依赖一个 **派生索引**（向量检索），可从真相源重建、可随时丢弃。所有写入经 **写入网关**：先检索去重 → 写 → 校验；更新用 **supersede**（有替代）、退役用 **archive**（无替代），**不原地改写、不删除**。检索复用既有混合检索引擎（向量 + 关键词），按其承载知识库的成长阶梯**提前打开向量窗口**（见全局 KB 的 KB-0003）。

理由：真相源需可回退、可迁移、人可读；派生索引可丢弃使架构可逆、无锁定。生命周期语义保留"曾认为 X、为何改 Y"的决策链，这是纯 git 无法表达的。提前打开向量窗口是产品决策（记忆包的检索体验是核心，且引擎已存在），非增长触发。

Considered options:
- A Markdown 真相源 + 派生索引（采用）——git 回退免费、零迁移、可审。
- B 向量库单源（弃）——丢版本 / 人读 / 可迁移，且本地向量库非真数据库。
- C 结构化数据库单源（弃）——本周成本高、脱离既有库、Markdown 可读性丢失。
- D Markdown + sidecar 元数据（延后）——企业级 ACL / 并发到来时的自然演进。

Consequences: 新增"索引一致性"责任（条目级增量重建、hash 跳过未变、孤儿清理、全量重建兜底）；写入者必须经网关并遵守生命周期字段。
