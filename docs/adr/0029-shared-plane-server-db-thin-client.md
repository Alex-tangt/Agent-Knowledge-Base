# 0029 跨设备共享面：服务端权威 DB + 薄客户端（远程 MCP）

Status: **proposed**（2026-09-19 owner 定方向；**不实现**，仅固化形态与前置）。

> 个人模式已落地（#52 一键部署 / #53 全新 WSL 验收）。本条只回答「**共享面**长什么样」，
> 不动当前代码；实现以解冻前置为准。共享 / 云仍在**冻结区**。

Amends: **ADR-0025**（把 D16「共享模式 = DB 即真相源」从同机 / 未来提升为**跨设备共享面的形态定义**；
把 D7-B「联邦服务」从"后延"改为"**本 ADR 指方向、实现仍后延**"）。**不 supersede** 任何 ADR。

Relates: ADR-0006（Markdown 基表，**收窄到个人面**）、ADR-0013（daemon/proxy 拓扑）、
ADR-0018（云多租户治理；**deferred**，本 ADR 承其 D1=B / D2）、ADR-0019（store 端口）、
ADR-0024（包化）、#25（云 spike）、#32（网关）、#33（网络化 store）、#34（隔离套件）、
#38（联邦，后延）、#39（租户泄漏修复，前置）、ADR-0028（部署 / 跨平台）。

## 背景

- 个人模式的形状已定并交付：**单 daemon + 单基表 + Markdown/git 真相源 + 派生 ANN**，
  天然私密（`ADR-0013` / `ADR-0025` / #52/#53）。
- 下一根轴 = **跨设备共享同一知识**：多台电脑（或多人）访问**同一份**服务端数据。
- 既有地基（现多属冻结区）：`VectorStore` 端口与 `MEMORY_STORE_URL`（#33，本地 `path=` / 自建
  `url=` / 托管 `url=+api_key=` 同一 API）；网关 authn→身份→authz（#32）；远程 MCP（`/mcp`
  streamable-http）；embedding 端点 `/v1/embeddings`（#43）。
- `#25` 一手实测：托管云**没有**服务端强制的行级隔离 / RBAC / 审计（Zilliz Free 的 `tenant`
  是纯客户端约定）→ 隔离只能**自建于网关**（`ADR-0018 D2`）。

## 决策

- **D1 两轴不变**：所有权（个人 / 共享）× 部署（本地 / 托管）正交（承 `ADR-0025`）。
  **个人面 = 本地、私有、单基表（不变）**；**共享面 = 服务端权威服务**（可自建于内网 / LAN，
  或单用户托管）。二者可在同一客户端**并存**。
- **D2 共享面真相源 = 服务端 DB 权威**（承 `ADR-0025 D16`）：条目**正文 + 元数据**入 DB
  payload，**索引与数据同源**；共享域**不用** git commit / 代目录 / 指针切换 / 查询时惰性重建
  （那些是**本地面**机制，不外溢）。个人面仍「Markdown + git 为基表」。
- **D3 客户端 = 薄客户端**：客户端只跑 `proxy`（stdio ↔ 远程 MCP），**不载模型、不建本地索引**；
  **embedding 由服务端提供**（复用 `/v1/embeddings` 思路）。多机一致、客户端极轻。
- **D4 身份 = 先个人多设备、架构预留多租户**：起步用 **token**（一设备一令牌）；形状按多租户设计
  （`tenant` + `classification` / `residency` + **网关唯一强制**，承 `ADR-0018 D2` / `#32`）；
  每次 `tools/call` 审计归属到 agent（承 `ADR-0025 D15/D19`）。
- **D5 域寻址（共享面必须）**：工具面要能寻址「**本地私人域 vs 共享域**」。这与个人模式
  「**写侧无域寻址**」（`ADR-0025 D19`）**相反**，是本面引入的**接口变化**——如实登记为缺口
  （呼应 D19 对 D14 的修正：谓词接缝在，具名 / 域寻址不在）。
- **D6 版本 / 审计自建**：DB 权威下，条目的**版本**与操作**审计**须自带（复用网关审计 JSONL；
  最小版本模型：`status` 软删除 + `updated` + 操作日志）。知识语义（supersede/archive/去重/
  条目粒度）与嵌入（BYOE）仍属 app 层（承 D16）。
- **D7 部署形态（先个人多设备）**：一个 **memory-agent server**（远程 MCP）+ 一个 **DB**
  （Qdrant server 或 Postgres+pgvector）+ **网关**；客户端 `proxy.py` 指向该 server。
- **D8 前置与解冻顺序**：**#39（租户泄漏）第一修**；复用 **#33**（网络化 store）；
  **#34**（隔离绕过套件）作验收硬项；**#38 联邦 / 同步暂不做**。
- **D9 非目标**：不做**本地优先 + 同步 / 冲突合并**（薄客户端无本地写，故 v1 不需要「真 DB 之外的
  冲突处理」）；**不依赖**托管云的行级隔离 / RBAC（`#25` 结论）。

## 理由

- **一致性**：共享走 DB 权威是 `ADR-0025 D16` 的既定方向；本条只是把它从"同机共享服务"
  推进到"跨设备共享面"，并补上**客户端形态**与**身份范围**两个未定项。
- **反碎片化**（`ADR-0025 D1` 理由）：共享的是**同一份服务端基表**，多设备不各建索引。
- **薄客户端最省**：客户端不需要模型/索引；embedding 集中在服务端（呼应 D17/D18 的「一份引擎只付一次」）。
- **隔离只能自建**：`#25` 已证托管云无强制行级 → 强制点必须在我们的网关（`ADR-0018 D2`）。

Considered options：

- **客户端形态**：**薄客户端（采用）**｜本地优先 + 同步（后延，`#38`，冲突解决成本高）｜混合（未来）。
- **真相源**：**DB 权威（采用，承 D16）**｜git/Markdown 仍权威 + DB 派生（弃：多写者走 git 争用）｜
  DB 权威 + 镜像回 git 审计（弃：两源一致性成本）。
- **部署**：**自建 / 单用户托管（采用）**｜直接依赖托管云行级隔离（弃，`#25`）。

## Consequences

- **个人面完全不受影响**（本轮已交付）；共享面为**新增形态**，与个人面**并存**。
- 引入新的运行面：服务端进程、DB、真实身份、**域寻址**、版本 / 审计；**接口变化**（D5）需在实现前
  先定 API（本 ADR 只定方向）。
- **冻结区不因本 ADR 解冻**：解冻以 `#39` 等前置为准；`#38` 明确后延。
- 与 `ADR-0006` 的冲突以**平面归属**化解：文件 + git 基表是**个人面**模型；共享面换 DB 权威（D2）。

## 实现缺口 / 未决（实现前须再定）

1. **域寻址 API 形状**（D5）：工具面如何表达「私有 / 共享」目标；与 `section`（全局 KB 内分区）的
   关系。
2. **条目版本模型**（D6）：最小可审计版本（append-only 操作日志 vs 行版本号）。
3. **隐私边界**：私人域条目**不自动进共享**；是否要显式「发布 / 提升」动作。
4. **embedding 中心化**：服务端出向量（薄客户端）与「客户端 BYOE」的取舍与缓存。
