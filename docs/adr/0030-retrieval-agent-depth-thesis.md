## 背景

**触发**：LLM 已进**我们的代码**（插件内驱动子会话，`memory_agent/plugin/memory-research.js`）。
ADR-0026 的约束前提——"循环跑在宿主 agent、本包只交付 skill + MCP 工具、**强制多跳/充分性/终止不在
可及范围**"——**已解除**。循环归我们，机制（预算 / 终止 / 委派 / fan-out / 校验）**可落成代码契约**，
**in-package harness / runtime**（ADR-0026 D1 的"层 2"剩余部分）**可做**。

**现状**：检索 = 条目级混合（BGE-M3 + BM25 + DBSF）；agent 面 = **skill 规劝**（迭代 ≤2 跳）+
**子代理隔离**（形态 A / B）。实测（#48 Phase B，外部语料）迭代 +10.2pp 答案 / +9.1pp 召回、
裸改写无增益、**LLM 早停 35.8%**——机制证据，**非产品增益**（ADR-0026 D5）。

**问题**：在不脱离本项目背景（记忆能力包 / 文件+git 基表 / MCP / 生命周期 / 治理）下，如何把
"**文档检索 agent 做深**"、且是**可上简历的深度**？

## 决策

- **D1 thesis**：把记忆能力包从"**检索工具 + 提示规劝**"升级为"**我们自己控循环的检索 agent
  runtime**"；深度落**三根轴**：**A agentic search（机制）/ B grounded verification（信任）/
  C version·conflict（独有角度）**，全部以 **H 的 harness** 产出**统计显著**的数字。
- **D2 平台先行（H = 公共基座）**：先建 **in-package harness + runtime**——工具注册 + **代码控循环**
  （预算 / 终止 / 委派）+ **轨迹 record/replay**（`run_hash` 确定性）+ **可验证 outcome 的场景评测
  harness**（LLM 在环、留出集、bootstrap CI，沿 ADR-0021/0026 口径）。**A/B/C 均 blocked by H**。
- **D3 边界（不变量）**：**冻结区不动**（共享 / 云 #38/#34/#55；**#39 于 2026-10-07 由 owner
  解冻开工**——它是已定位的真实跨租户泄漏，解冻时第一件修）；**不碰检索默认 / 合成**
  （沿 ADR-0026 D6）——新能力走"**加只读工具 + 代码循环**"；**保 ADR-0025**（基表 = 文件 + git、
  写侧单目标、治理口径）。**不新建服务端 LLM、不动 daemon 确定性。**
- **D4 序**：**H（薄）→ A → B**（原为 `H→A→B→C`，**2026-10-07 收窄**：C 后延，见 D8）；
  **D（multi-agent 深度研究）暂缓**——成本最高（≈15× token），且 **blocked by 一张 in-domain
  多跳/冲突评测集**（见 D5）。
- **D5 in-domain 评测集是"正证"前置**：ADR-0026 D5 已定**外部语料只能反证、不能正证本 KB**。
  要用**本 KB** 证明任何增益（含 C / D），必须先建**本语料的多跳 / 冲突评测集**（分层 gold evidence）。
  该集是独立票（E），**C / D 均 blocked by 它**。
  **2026-10-07（D8）重划**：C 后延后，E 不再是 A/B 的前置，**降优先级但不取消**；线②的
  "可验证前置"改由 **#71（标准集适配 + 导航探针 + 一次性基线）** 承担，口径仍是**只作机制证据**。
- **D6 外部语料只作机制证据**：H/A/B 的外部语料结论**不得当产品增益引用**（沿 D5）。
- **D7 评测 ⊥ 运行时 + trace 契约**（H 的边界与锚点；2026-10-03 补，评审发现代码已引用本
  编号而 ADR 缺该节——先有实现后补决策属倒置，此处补正）：
  - **D7.1 唯一契约**：`memory_agent/trace.py`（Trace JSONL）。运行时（`agent_loop/`）只**写**、
    评测（`eval/harness/`）只**读**，**运行时不得 import 评测**（静态 + 运行时双检守卫）。
  - **D7.2 确定性锚点 = `run_hash`**：轨迹**内容**哈希（不含随机 `id`、不含自指的
    `meta.run_hash`）；同一输入两次运行得同一 hash；`replay` 逐位复现且 hash 相同。
  - **D7.3 停止口径**：由**代码**判定——**确定性** = `budget` / `no_new_ids`；**非确定性** =
    充分性信号（默认 = 模型给出终结回复；`SufficiencyChecker` 是可替换接缝，**不得**把模型
    自报当确定性判据）。评测**按 stop 分类**报答案正确率；gold 覆盖只作**筛查**
    （`gold_unreached`），不当危害证据。
  - **D7.4 证据语义**：`evidence_ids` = **真正展示给模型**的条目（受 `max_evidence` 上限）；
    本轮命中记录仍完整保留在轮次里。**只有一个来源**，不允许"上报一套、展示另一套"。
  - **D7.5 H 与 E 的分工**：H 只交付"**能跑通评测通路的确定性桩场景集**"（stub LLM / stub 工具、
    dev / holdout 切分、bootstrap CI）；**in-domain 多跳/冲突评测集归 E**。H 的桩集数字是
    **通路证明**，**不得当本 KB 的产品增益**（沿 D5 / D6）。
  - **D7.6 工具面**：循环只做"**只读工具 + 代码控循环**"，模型可见的工具目录来自
    `ToolRegistry.list_tools()`；工具派发不得引入写路径，**不碰检索默认 / 合成**（沿 D3）。
  - **D7.7 regret（反事实续跳）**：离线、可选、只在"停了 ∧ 错"子集上抽样；**本阶段不实现**，
    属 H 的后续扩展。
- **D8 路线收窄为 `H→A→B`（2026-10-07 owner 拍板）**：**C（version / conflict 检索）后延**，
  **E（in-domain 多跳/冲突评测集）随之重划**，理由与触发条件如下。
  - **依据 = 一次分钟级 census，不是判断**：当日量测 —— **全索引 260 条中退役条目 = 0**
    （唯一可写 KB 的 40 条无退役；**只读语料在工具层就不可能退役**）。D1 给 C 的前提是
    "本仓有 supersede / archive / git 历史这条**其他作品集给不出**的版本轴"——**轴存在，
    但轴上没有实例**；给实例数为 0 的现象做机制，违反决策闸门硬规矩②（先 census 再建机制）。
  - **C 的触发条件（写在这里，届时直接开工）**：出现**首条**真实退役条目，**且**量测到它
    进入 top-k 并影响答案（口径见 `CONTEXT.md`「视图」词条）。
  - **票务落点**：**#65（E）/ #67（C）关闭**，依据记在本条 + 票评论；**#66（D）仍 backlog**。
  - **A / B 不受影响**：#63（A）的 blocked-by 改为 **#71**（评测基座），#64（B）顺延其后。

## 理由

- **复用开源基线优先**：深度机制与评估法沿用一手来源（Anthropic 多 agent 研究系统 / Building
  effective agents、Agentic RAG survey `2501.09136`），不重造；机制层复用本仓 `agentic-rag-loop`
  的三条可迁移结论（**终止 = 多条件 OR**、**gap-driven 下一跳**、**显式充分性 + 弃答**）。
- **廉价测量优先**：H 先给"**可复现的重放 + 统计**"，任何机制上线前先在其上量，避免"demo 式做深"。
- **差异点在 C**：通用 RAG 语料**没有版本轴**；本项目有 **supersede / archive / git 历史**，
  "冲突 / 时效感知检索"是**通用作品集给不出**的角度——最值得作为简历叙事支点。

Considered options：

- **E+ 分阶段 H→A→B→C（采用）**——深度完整、每轴独立可验收；代价是面宽，须按票收窄。
- **A / B / C 单轴（备选）**——见效快，但深度偏单一：A 偏工程、B 偏校验、C 最差异化但前置重。
- **D 单轴 multi-agent（暂缓）**——规模叙事亮，但成本最高且无 in-domain 集则无法证明。

## Consequences

  **C**（version/conflict 检索）、**E**（in-domain 多跳/冲突评测集）；**D 记为 backlog**。
- **依赖边**：A/B **blocked by H**；C/D 另 **blocked by E**。**2026-10-07（D8）**：C 后延 →
  该边只对 D 有意义；**A（#63）的 blocked-by 改为 #71**（线②评测基座）。

  不可裁决不自动择一）随 D8 挂起**，触发时直接启用。

**结果**（前两条预注册，第三条**事后**）：

2. **额度机制事实**：A1 实际展示深度 **mean 6.0 / p50 5 / max 15**（176 可答口径），

   早停层 A1 0.6683 vs 同层 top-15 天花板 0.8573。
   **判据对齐错了**：充分性信号测的是"我能不能答"，而评分要求"证据齐不齐"

3. **深度匹配对照（事后、探索性，不得当预注册结果引用）**：`A1 − Cad = +0.011364`

**结论（可引用口径）**：在这套外部语料上，**agent 循环没有带来可测的检索质量增益**——它相对

增益来自"**多展示 1–2 条**"，**不来自"更聪明的选择"**；代价 = 448 次 LLM 调用 / 3748 s 墙钟。
⇒ **下一个杠杆是循环的停止判据**（早停导致额度花不完），**不是再加工具**。
⚠️ **这一句已被「实测补充三」（A‴ 的逐轮边际收益）修正**：停止判据是**症状**不是病根——见下。

2. **`fallback` 加固不单开实现票**（判定未决）：触发条件 = 出现 N ≥ 390 的测量，或在**真实用户

3. 新开缺陷票：**`memory_get` 的 `entry_id` 传成 list → `TypeError: unhashable type: 'list'`
   中止整题**（`AgentLoop._dispatch` 只捕 `KeyError`；`MemoryNavToolRegistry._load` 对非 str 有

## 实测补充二（A‴ · #76，2026-10-08）：**缺 gold 会不会导致"错误信息"？**

> **事后 / 探索性，不属预注册**；不改 D1–D8，也不改上一节的 A″ 结论。
> 证据 `experiments/agentic-rag-census/phase_a2/a3_results.{md,json}`；Lead 独立复算 `lead_verify_76.py`。

**为什么问**：A″ 只量了**筛选指标**（条目级证据召回），且**预注册明确排除了答案判分** →
它的负结果**不能**推出"这个过滤器产出的报告更差"。owner 追问：gold 标注的信息必要吗？缺了会产生错误信息吗？
（已知反例：`mhr2475` 召回 0.25、答案却是对的——模型用参数知识答的。）

### 口径事实（先看这条：它推翻了本票 issue 的前提）

A1 轨迹里**只有 66/176 可答题有答案**——运行时只在**模型最后一步是 `ANSWER:`** 时才写 `final.answer`
（`memory_agent/agent_loop/loop.py:193`：`answer = last.value if last.kind == "answer" else None`）
⇒ **110/176（62.5%）可答题没有任何答案产出**。按停止原因：`answer` 66/66 有答案；
`budget` 49 / `no_new_ids` 35 / `fallback` 25 / `insufficient` 1 **全部 0 答案**。

### 结果一：缺 gold **没有**导致答案变差（可判分的 66 题）

| | gold 齐（recall=1） | gold 不齐（recall<1） |
|---|---|---|
| 答案对 | **21** | **43** |
| 答案错 | **1** | **1** |
| 小计 | 22（95.45%） | 44（97.73%） |

- 主口径 `phase_b.det_match`：62 题确定性判定 + **4** 题异模型裁判（`qwen3.7-max`，**不透露** gold 齐不齐）；
- **三档 matcher 同向**（严格档：齐 13/22 = 59.1% vs 不齐 37/44 = 84.1%）
  → **没有任何一档支持"缺 gold → 答得更差"**；
- `stop=answer` 且 gold 不齐的 44 题：错误率 **1/44 = 2.27%**（严格档 7/44）。
- **功率警告**：全样本只有 **2 个错答案**（一格一个）⇒ 这是「**没有证据显示有害**」，
  **不是**「证明无害」。

### 结果二：真正的伤害在两处，**都不在"召回"上**

1. **无答案率 62.5%**：凡是模型没显式说 `ANSWER:` 的收尾路径（预算用尽 / 无新条目 / 协议失配），
   产品**什么都不产出**。对"过滤器"定位而言这是**头号失效**，而且「没找到」与「没敢答」
   在外部**不可区分**。
2. **点名来源的约束不被核验**（零 LLM 可复算）：**175/176（99.4%）** 的问题**显式点名**了来源；
   在 328 个「(提及来源, 该来源在 gold 里有文章)」对里——
   - **A1：82/328（25.0%）对、66/175（37.7%）题**没把该来源的 gold 篇带进证据；
   - **C15（一次性 top-15）：36/328（11.0%）对、33/175（18.9%）题** → **一次性检索明显更守约束**；
   - 交叉：A1 这类"致盲"题中**有答案的 26 道，判对 26 道（100%）**
     ⇒ **答案对，但问题里点名的来源从未被核**——这正是"AI 致盲"（局部自洽 ≠ 完整）的实证形态。
   - **口径注记**：以上用**严格定义**（"该来源的 **gold 篇**没进证据"）。宽松定义（"该来源**任何**文章
     都没进"）会小一半：A1 38/328、35 题。**两个数必须随口径一起引用**（Lead 复算时先撞上这个 2× 差异，
     已定位为口径而非错误）。

### 结论（可引用口径）

- **A″ 的负结果不该被读成"过滤器产出的报告更差"**——它只是"同额度下没多找到该找的文章"；
  而在真正产出答案的题上，gold 不齐**没有**伴随更差的答案。
- 但它**也不是"缺证据无害"**：伤害在**约束核验**与**无答案产出**。
- ⇒ **#64 B（grounded verification）的靶子应从"找齐 gold"移到「约束满足 / 可核验」**
  （后者有零 LLM 可复算的判据面），并把"非 `ANSWER` 收尾即无产出"单独立票。

**建议处置（待 owner 确认；本 ADR 不据此改既有决策）**：新增票 = 运行时在**非 `ANSWER` 收尾**时
也要产出"带缺口的报告"（而非 `answer=None`）。

## 实测补充三（A‴ 讨论，2026-10-08）：**逐轮边际收益**——停止判据是症状，不是病根

> 零 LLM，只读已入库轨迹：`experiments/agentic-rag-census/phase_a2/lead_round_yield.py`。

| 轮次 | 到达该轮 | 平均新增条目 | **平均新增 gold** | 该轮有新增 gold 的题占比 |
|---|---|---|---|---|
| 1 | 176 | 3.76 | **1.22** | 70.5% |
| 2 | 100 | 1.25 | **0.17** | 15.6% |
| 3 | 65 | 0.56 | **0.04** | 4.2% |

- 后续轮（2/3）贡献的 gold 槽位合计 **21 / 461 = 4.6%**；
- 首轮 0 gold、被后续轮**救回**的题：**6 / 176**；
- `memory_search` 返回 0 新条目的轮次 17；同题内 query 重复仅 2 次（**不是** query 撞车）。

⇒ **模型说"够了"在它能看到的世界里是理性的**：循环继续下去本来就没东西可拿。
**真正的病根是"迭代在同一个邻域里打转，从没走到首轮排名的第 6–15 名"**——
迭代若不**换检索面**（变大 k / 走 `grep` / 读全文 / 来源过滤），多跑的轮次只是重复付费。
**推论**：一次 `k=15` 的检索（0 次 LLM 调用）在证据召回上比 3 轮 `k=5` 的循环（~450 次调用）高 **0.16**。
