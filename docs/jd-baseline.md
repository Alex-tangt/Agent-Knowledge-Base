# Agent 开发岗 JD 基线（决策依据）

> **用途**：本项目所有"要不要做 / 先做哪个"的裁决，**J5（JD 命中）以此表为准**；新增能力前先查此表。
> **性质**：决策**输入**，不是 ADR，不是实验结论。方法沿「复用开源基线优先 / 廉价测量优先」的纪律。
> **样本**：4 份 JD（2026-10 由 owner 提供；卓望 · 快手 · 神州信息 · 中城交）。
> **诚实边界**：频次 = **这 4 份的频次**，不是市场频率；**样本能"排除"，不能"证明"**。
> 追加 JD 时只改本表，不改结论以外的散文。

## 二、命中对照（本项目现状）

| 要求 | 现状 | 证据 / 缺口 |
|---|---|---|
| Python | ✅ | `memory_agent` / `ragcore`（可安装包 + 579 项单测） |
| 工具调用（Tool Use） | ✅✅ | 工具注册表 + `TOOL:` 派发协议 + ACI 工具目录（#62） |
| 记忆（Memory） | ✅✅✅ | **本项目 hero**：文件+Git 真相源 + 生命周期 + 跨会话检索 |
| 规划（Planning） | ⚠️ 部分 | 循环是**代码控**（预算/终止），无显式 planner；`#66 D` 暂缓 |
| 编排 / 多 Agent | ⚠️ 部分 | `#60` subagent 委派（独立子会话）+ `#61` plugin 组合工具；**缺 orchestrator/并行**（#66） |
| Prompt 工程 | ✅ | 协议式输出（`NEXT_QUERY`/`ANSWER`/`INSUFFICIENT`/`TOOL`）+ 解析容错 + 单测 |
| 工程化 / 可上线 | ✅✅ | 一键部署（Windows/WSL 幂等 + dry-run + 备份）、共享 daemon、boot 冒烟、579 测试 |
| RAG / 向量库 | ✅✅✅ | Qdrant hybrid（BGE-M3 + BM25 + DBSF）+ 按需重排 + 51 题确定性评测（recall@5 0.9185→0.9685） |
| 评测体系 | ✅✅✅ | trace 契约 + `run_hash` 确定性 + holdout + bootstrap CI（**JD 里只有 1/4 明写 → 稀缺**） |
| MCP / SKILL | ✅✅ | MCP server + 随包 skill + 注册落位（**1/4 明写且正中**） |
| 框架生态 | ❌ | 自建 runtime，不用 LangChain/AutoGen → **需准备"为什么不用框架"的话术**（可辩护性 J6） |
| DB / MQ / 微服务 | ❌ | 仅 1/4 且为"熟悉"级 → 见 §三 裁决 |
| 微调 SFT/RLHF | ❌ | 2/4 但均加分项 → 不做 |

## 三、裁决（本项目据此定）

| 结论 | 依据（频次） | 对应票 / 资产 |
|---|---|---|
| **必须保持并作为叙事主线**：Agent 核心模块（工具调用·记忆·编排）+ RAG + Prompt + 工程化 | 4/4 / 4/4 / 4/4 / 3/4 | 本项目已有；`A`（#63）工具化导航继续 |
| **首要求职叙事**：评测体系（确定性 trace + bootstrap CI） | 仅 1/4 明写，但**要做深极难** → 稀缺度高 | `H`（#62 已合）+ `E`（#65 收窄） |
| **值得补的缺口**：多 Agent / 协作编排 | **3/4 提到** | `#60/#61` 已有部分命中；`#66 D`（暂缓）应据此**重新评估**，或至少把"受控委派 + 上下文隔离"讲成编排经验 |
| **维持不做**：数据库 / 消息队列 / 微服务 | **1/4 且为"熟悉"级** | 与「决策闸门 A」否决结论一致；不为此投入（Redis/MySQL 等触发阈值另表） |
| **明确不做**：微调 SFT/RLHF | 2/4 但均加分项 | 成本高、与主题无关；记录在案，遇硬要求再议 |
| **必须准备话术**：为什么自建 runtime 而不用 LangChain/AutoGen | 3/4 问框架生态 | 答案要点：端口可替换 / 循环可控可测 / trace 契约与确定性评测 / 不引入框架的黑盒与版本风险 |
