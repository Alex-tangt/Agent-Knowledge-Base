# 个人记忆基座独立产品计划

2026-10-11。依据 ADR-0032 与[固定源码研究](architecture-memory-base-source-study-2026-10-11.md)。这是可执行的产品化计划；完成状态由[交付任务板](memory-base-delivery-plan-2026-10-11.md)与实际验收记录决定。

## 产品范围

Windows 家用 PC 是首个正式部署平台，手机经 Bubble 后端使用，coding agent 通过共同 MCP 接入。产品是一个人的内容持久层：应用提交的原文、真实项目文件的只读地址，以及从这些输入另存的加工产物。多个 agent 共享内容；agent 身份用于来源与能力约束。部署以本机和已有私有网络为边界。

首个独立版本交付原文追加/读取、项目来源登记与当前文件读取、路径范围列举/检索、版本核验、显式失败、完整备份恢复与宿主使用规约。学习、个体偏好晋升和自动技能生成保持独立后续层。人的开发授权不能替代对某项全局偏好的批准。

## 保留、扩充与剥离

| 模块 | 处理 | 自持的合同与维护责任 |
|---|---|---|
| `memory_base` 共同入口、来源解析、路径、回执 | 产品核心，独立 Python 包 | 原文、幂等、权限、来源版本与错误；HTTP/MCP 一致；向后兼容旧 URI |
| OpenViking 0.4.23 服务 | 继续固定依赖并复用资源/向量/原生持久化 | 禁止自动改写 capture；ACL 不视作可丢弃缓存；整个 data 与恢复流程归产品负责 |
| 进程外串行 GGUF 嵌入 | 保留已证明的部署适配 | 同一模型单锁；并发存活、模型哈希、资源与故障证据；不回退到已崩溃的进程内实现 |
| 旧 `memory_agent` / `ragcore` | 保留资产，退出新产品安装及运行依赖 | 历史评测仍可复跑；旧注册不能混入新服务；不因产品化改写负结果 |
| `legal_web` | 仅历史保留 | 不安装、不启动、不以其测试代替新产品验收 |
| MemOS Python / Local | 保留研究引用，不放入首版依赖 | 将来按真实任务选 runner/reader/反馈等有边界的模块；不新增第二套原文主库 |
| RAGFS 与原生持久化裁剪 | 触发式后续 | 只有明确的包体/兼容/维护瓶颈才受控 fork；同时承担 binding、平台 wheel、迁移、ACL、备份与升级 |

独立意味着拥有接口、数据与部署流程，并允许成熟开源依赖；不以重新实现底层数据库作为完成标志。发布产物只包含 `memory_base`、安装入口、依赖约束和规约，不携带课程产品与实验目录。

## 来源与版本清单

OpenViking 的研究基线为 `v0.4.23 / df32bf6e50a40843438f9491a26069ca4bd08f1f`，安装的 704 个共有 Python 文件与 checkout 归一化文本一致；原生构建产物未核对。根/Python 源码标 AGPL，Rust 子目录的 Apache 标注不能推导整个裁剪产物许可。MemOS 固定 `a7367d07e55db61099f7b4e2c1108bc5831a24f3`，Python manifest 标 Apache-2.0、Local manifest 标 MIT；它是 main 快照，未选为稳定模块发布。这里只记录上游声明和已核对范围，沿用 owner 在 ADR-0032 D8 接受的产品方向。

每次实际纳入新模块，记录入口、固定 SHA、纳入文件、相伴 prompt/schema/迁移、依赖与源码声明、测试、上游更新方式及退出办法。现阶段不在同一运行环境安装 MemOS Python；其 `openai<2` 与正式环境的 `openai==2.54.0` 约束冲突。

## 迁移与升级

1. 原有 capture URI、请求地址、正文和 `capture.json` 保持有效。新增接触日与逻辑路径不搬移旧原文；未知接触日明确 unknown。
2. 来源登记是持久控制状态，项目正文与项目版本仍归真实 repo。首次登记只读允许子树；源根变化由本机管理命令处理，读取和搜索重新核验，不能暗中改为旧快照。
3. 升级前完整冷备份并封存清单。依赖固定版本，先在独立数据根复跑内容、索引、授权、回执兼容和恢复；通过后再切正式环境。失败恢复备份及旧运行环境，不让旧实现读取未知新版持久格式。
4. 数据格式带 schema；新增可选字段兼容旧对象。任何不可兼容的格式变更需有旧→新迁移、校验与退出记录，不能直接重建整个数据目录来掩盖权限/状态丢失。

## 数据出口与恢复

完整备份保存 native data、来源登记和可验证清单；目标运行路径、端口、源码与模型路径由目标部署配置。运行环境可依约束重装，凭据由系统凭据库单独提供或安全重发，备份不携带 PID、日志或明文令牌。恢复必须在空数据根先验证文件清单/哈希，再验证正文、搜索和拒绝访问。

退出 OpenViking 时，以原文及回执、项目来源引用、确认状态与权限规则为迁移对象。向量可以重算，确认状态和权限不能依靠模型重新推断。人可读的原文出口应通过公共读取/列举获得；整个 native data 冷备份是恢复介质，不假称通用跨引擎交换格式。

## 发布门槛与后续触发

首版需在独立产物/数据根运行、保留真实 Bubble 与 Codex 接入、通过全量已有单测/harness/冒烟，并完成当前项目增改删/失联及恢复证据。所有成功声明列明具体平台和宿主；注册成功不等于实际调用成功，POSIX 尚未验收时不标跨平台发布完成。

后续由真实缺陷触发：词法项目检索漏掉有证据的任务→增加有源版本的语义召回；重复任务与反馈积累→适配一个经验加工模块；上游包体或原生升级成为维护瓶颈→受控裁剪；恢复点损失不可接受→自动备份策略。无需用户日常审查每个历史版本，系统保存提交回执和可验证恢复点，人只处理需要其决定的事项。
